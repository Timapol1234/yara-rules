# YARA Rules — детект вредоносного ПО по содержимому файлов

Набор учебных **YARA-правил** для обнаружения вредоносных артефактов на конечной точке: веб-шеллов, подозрительного PowerShell и исполняемых файлов Windows. Проект показывает навык написания **файловых сигнатур** — второй половины детект-контента SOC-аналитика (первая — правила по логам в формате Sigma).

> Учебный проект на домашнем стенде (WSL/Linux). Демонстрирует написание и тестирование детект-правил, работу с текстовыми и байтовыми сигнатурами, тюнинг против ложных срабатываний.

---

## YARA vs Sigma — в чём разница

| | **Sigma** | **YARA** |
|---|---|---|
| Ищет по | событиям в логах (SIEM) | **содержимому файлов и памяти** |
| Отвечает на вопрос | «что произошло» | «что это за файл, не вредонос ли» |
| Где применяется | SOC / SIEM | антивирусы, песочницы, DFIR, threat hunting |

Аналитик пишет и то, и другое. Этот репозиторий — про YARA; парный проект по Sigma и детекту по логам: [SOC-lab](https://github.com/Timapol1234/SOC-lab).

## Реализованные правила

| Правило | Что детектирует | Тип сигнатуры | MITRE ATT&CK |
|---|---|---|---|
| `PHP_Reverse_Shell` | PHP-реверс-шеллы (pentestmonkey и аналоги) | текстовая, `3 of` | T1505.003 (Web Shell) |
| `Windows_Executable` | PE-файлы Windows (EXE/DLL) по magic-байтам | байтовая, `at 0` | — |
| `Suspicious_PowerShell` | обфусцированный / загрузочный PowerShell | текстовая, `2 of` | T1059.001, T1027 |
| `EICAR_Test_File` | стандартная тестовая строка EICAR | текстовая | — |

## Структура

```
yara-rules/
├── README.md
├── rules/
│   ├── webshell_php.yar
│   ├── windows_pe.yar
│   ├── powershell_suspicious.yar
│   └── eicar_test.yar
├── samples/               # тестовые образцы
│   ├── fake_pe.bin        # безвредные лежат в репозитории
│   ├── clean.txt
│   └── README.md          # «вредоносные» тест-образцы генерируются локально
└── scan.sh                # прогон всех правил по каталогу
```

## Как запустить

```bash
sudo apt install -y yara          # установка

# (по желанию) сгенерировать «вредоносные» тест-образцы — см. samples/README.md

# один файл против одного правила
yara rules/windows_pe.yar samples/fake_pe.bin

# весь набор рекурсивно по каталогу образцов
./scan.sh                          # = ./scan.sh samples
./scan.sh /путь/к/проверяемой/папке
```

После генерации всех тест-образцов каждое правило находит свою цель, а `clean.txt`
не срабатывает нигде:

```
PHP_Reverse_Shell      samples/webshell_test.php
Windows_Executable     samples/fake_pe.bin
Suspicious_PowerShell  samples/suspicious.ps1
EICAR_Test_File        samples/eicar.txt
```

## Ключевые приёмы, отработанные на практике

- **Текстовые сигнатуры** (`$s = "..."`) и **байтовые** (`{ 4D 5A }`) с масками
- **Позиционные условия** (`$mz at 0`) — привязка сигнатуры к смещению в файле
- **Тюнинг против ложных срабатываний**: условие `N of ($s*)` вместо одной строки — баланс между пропуском атаки (false negative) и лишними тревогами (false positive / alert fatigue)
- **Гигиена сканирования**: правила хранятся отдельно от проверяемых данных, чтобы правило не срабатывало на собственном тексте
- **Привязка к MITRE ATT&CK** в блоке `meta`

## Возможные улучшения

- Модуль `pe` — правила по структуре исполняемого файла (импорты, секции, подписи)
- Правила по энтропии (детект упакованного/зашифрованного кода)
- Интеграция в пайплайн: авто-скан загрузок, выгрузка срабатываний в SIEM
